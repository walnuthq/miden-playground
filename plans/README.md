## Findings considered and rejected

First audit:

- `apps/api/.env` is committed: by design, it holds local defaults only and
  says so in its header.
- Path traversal through package names sent to the compile service: that
  service normalises paths when it opens a project, so this reduces to the
  input validation in plan 003.
- `pnpm audit` high advisory on `zod`: transitive through Para's `viem`
  integration; not fixable in this repo.
- Playwright in CI: declined by the maintainer for now; plan 005 does not add
  it.

Second audit:

- Upstream error text returned to clients and `GET /` listing the service
  URLs: the URLs are already public in the committed `wrangler.jsonc`, the
  status page's probe reads that route, and compile errors are meant for the
  user.
- Key material (`accountAuth`) in the tutorial store snapshots
  (`components/tutorials/*/store.ts`): the shared tutorial wallets, by
  design.
- Notes first seen before the node knows them are typed "public" for good
  (`lib/web-client.ts`, `wasmInputNoteRecordToInputNote`): plausible but
  unconfirmed, it depends on node behaviour that wasn't checked. Recorded in
  plan 016's maintenance notes; investigate before planning a fix.
- Splitting the global context so a sync tick doesn't re-render every
  consumer: real, but large and risky; revisit after plans 016 and 017 with
  a profile.
- Route-level API tests: need a Workers test pool and a database in CI; the
  pure helpers are covered by `node --test`.
- Selecting fewer columns in `getPackage` (`apps/api/db/packages.ts`): small
  gain, sizes not measured.
- A root `turbo test` task and a pre-commit hook: CI already runs both apps'
  tests by filter; low value.
- The Para branch of `account-notes-table.tsx` never resetting its loading
  state: wrong, its handler has a `finally`.
- Missing database indexes: every query is a primary-key lookup.
- `wagmi`, `viem` and the Para connector packages look unused in `apps/web`:
  they are required peers of Para.
- `.env.example` coverage and the `docs/claude` path references: checked,
  nothing missing or stale.

Plan 030 review (2026-11-11), not planned by decision:

- Stopping an abandoned example deploy before it submits
  (`deployAccount`/`consumeFundingNote` checking `abandoned()` before
  `execute`, `hooks/use-accounts.ts` and `hooks/use-fund-account.ts`). Today
  a deploy that outlives the switch still submits its funding transaction to
  testnet; the SDK then fails to apply it in the next workspace's store
  (the account isn't there), so nothing leaks, and plan 030's test guards
  that. The cost is a spent faucet note per abandoned deploy. Fixing it
  changes the documented "a switch cancels nothing" behaviour
  (`docs/claude/saved-projects.md`); revisit if wasted faucet notes matter or
  if an SDK bump makes plan 030's test fail.
- Plan 030's test ("a deploy that succeeds after leaving its example …",
  `apps/web/e2e/projects.spec.ts`) timed out once at 2 min during plan 031's
  `--repeat-each=3` run (2026-11-11, local, testnet); the rerun passed and no
  trace was kept, so the failing wait is unknown. Watched, not planned: if it
  times out again, keep the trace and re-measure the prover/submit deadlines
  and the switch time before changing any hold.
