But what happens when you import a contract that isn't verified?

Let's find out: click the _"Import"_ button below. It adds a counter contract built from the same script as yours to the Playground, as if it had been deployed by someone else: nobody has verified it yet.

<ImportButton />

Once the contract is imported, {props.counter ? <Link href={`/accounts/${props.counter.identifier}?tab=components`}>open its <em>"Components"</em> tab</Link> : <>open its <em>"Components"</em> tab</>}.
The Playground recognizes standard components such as **No Auth** and **Basic Wallet**, but the counter procedures are missing: _"This account has no verified custom account components"_.

The contract's code does contain these procedures, but they're only identified by their MAST roots. Without their names and signatures, the contract behaves like a black box: only applications that already know its interface can interact with it.

**So how can you verify this contract?**

You can verify its custom account components by uploading the source code that was used to build them.
