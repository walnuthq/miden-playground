Let's extend the counter contract with a new procedure that resets the counter value to zero.
Add the following **`reset_count`** method inside the **`impl CounterContract for CounterContractStorage`** block, after **`increment_count`**:

```rust
/// Resets the counter value to zero
fn reset_count(&mut self) {
    let key = Word::new([felt!(1), felt!(0), felt!(0), felt!(0)]);
    self.count_map.set(key, felt!(0));
}
```

Then declare its signature in the **`CounterContract`** trait, marked with **`#[account_procedure]`** so that it's exported:

```rust
#[component]
trait CounterContract {
    // ...
    #[account_procedure]
    fn reset_count(&mut self);
}
```

When you develop a smart contract, you write human-readable Rust code, and a compiler turns it into [Miden Assembly (MASM)](https://docs.miden.xyz/builder/glossary/#miden-assembly) code that the [Miden VM](https://docs.miden.xyz/design/miden-vm/) can execute.

Click the _"Compile"_ button to see this process in action. The result of the compilation is a Miden package (a **`.masp`** file), which contains both the compiled code and a manifest describing what the package exports.

Click the _"Metadata"_ tab: under _"Package exports"_, you'll find the procedures exported by the package, along with their signatures.

Only the compiled code is stored on-chain, and each procedure is identified by its [MAST root](https://docs.miden.xyz/reference/protocol/account/code), a hash of its code, rather than by its name.
The link with the original Rust source code is lost, and so are the procedure signatures, which you need to call the procedures with the right arguments.

Contract verification bridges this gap: it links the on-chain code back to its Rust source code and package manifest, so that anyone can read the source code and know how to call the exported procedures.
