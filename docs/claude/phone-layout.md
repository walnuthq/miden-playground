# Phone layout

Below 768 px (`useIsMobile`, the sidebar's breakpoint) the web app has a phone layout; desktop renders as before. `e2e/mobile` checks it in the `mobile-safari` (iPhone 14, WebKit, 390 px) and `mobile-chrome` (Pixel 7, 412 px) projects, and `mobile-small` (Galaxy S9+, 320 px) runs the sandbox spec: run them after any layout change, and keep each page from overflowing the screen's width down to 320 px (a phone zooms the whole page out).

- Header: the GitHub button and the network badge's block height hide, and the breadcrumb truncates (`min-w-0`) before the action row (`shrink-0`) overflows. It fits down to 320 px.
- The sidebar is a sheet: `AppSidebarView` closes it on navigation.
- Tables hide secondary columns with CSS (`mobileHiddenColumns` in each `columns.tsx`, `mobileColumnClassName` in `lib/table.ts`), so row actions stay on screen. A nested table goes under its label (`NestedTableRow`). Below `sm` (the 320 px phones), the accounts table wraps names and clips IDs (`narrowColumnClassNames`), and the procedures table hides the digest's copy button. `expectWithinWidth` checks an element against its clipping containers too, so a row action hidden inside a scrolling table fails it.
- The stock dialog is a grid whose column won't shrink below its content: a dialog with wide content (tables) needs `grid-cols-[minmax(0,1fr)]`, plus `max-h-[calc(100dvh-2rem)] overflow-y-auto`, at the call site (the transaction dialog has both).
- Buttons that show only their icon below `lg` keep their label as `sr-only lg:not-sr-only`, for an accessible name. Tutorial copy names them with `ButtonName` (see `tutorial-copy.md`).
- Script editor: the tabs row wraps under ~380 px (the settings and Compile go under the tabs), a files menu replaces the file tree, the console starts collapsed (split saved as `script-editor-layout-mobile`), the minimap is off by default, and the source is read-only (see `script-editor.md`).
- The tutorial is a panel stuck to the bottom of the screen (`MobileTutorialPanel`, `id="tutorial"` like the desktop panel), which reopens when a step's action is done. Toasts show at the top.
- `AppShell` is the app's layout with every action disabled, on every screen, shown three times in a row on a first visit with the same markup: as the root route's `HydrateFallback` (`routes.tsx`) before the SDK's chunks and WASM load, then, under the SDK-bound providers, as Para's `fallback` (`ParaProvider`: Para holds its children back until its own client is ready, `waitForReady`; an empty page otherwise) and as `MidenClientGate`'s stand-in for the page until the Miden client is ready (`miden-provider.tsx`). The gate shows it again on every network switch, which re-initializes the client; the providers above it (multi-signer, Bread, Para) stay mounted, with their connections. Don't give the SDK's `MidenProvider` a `loadingComponent`: it stands in for the providers too, and Para's, remounted, showed its fallback again a few hundred ms after the page was back, closing any open menu. Don't keep state in the shell that must survive a remount.
- The shell paints before the WASM because the entry's static module graph (`main.tsx`, `routes.tsx`, `AppShell` and everything it renders) imports nothing from `@miden-sdk/*` or `@getpara/*`: the SDK's eager entry awaits the WASM at module load, and a graph that reached it would wait too. The SDK comes in with the lazy root layout (`RootLayout` → `Providers`). `vite build` fails if the entry chunk's static imports reach either package (`shellIsSdkFree` in `vite.config.ts`, which prints the chunk path to the culprit), so a slip fails the deploy. Rules that follow: the shell uses the `*View` modules (`app-sidebar-view.tsx`, `header-view.tsx`, `network-badge-view.tsx`, `project-switcher-view.tsx`, `home/home-view.tsx`, `home/*-card-view.tsx`, `app-layout.tsx`), which import no SDK hook, no app hook built on them, and no module that does; the containers (`app-sidebar.tsx`, `header.tsx`…) import their view, never the other way round. The shell's providers (theme, query client, network, app state) are `OuterProviders`, around the router in `main.tsx`, so they need no router hook; the SDK-bound ones are `Providers`. `NetworkProvider` and `MidenFiReconnect` use `lib/utils/storage.ts` (the SDK's `createMidenStorage` layout, without the SDK). Tutorials and examples appear in the shell through their metadata (`components/tutorials/meta.ts`, `lib/examples/meta.tsx`): their steps and states need the SDK.
- Syncing pauses while the tab is hidden (`PauseSyncWhenHidden`, `NetworkBadge`'s interval): it pauses only an auto-sync that isn't paused yet, and resumes only its own pause.
