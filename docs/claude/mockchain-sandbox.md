# MockChain sandbox (`mmck`)

A sandbox whose chain runs in the browser: the app's client is a mock client (`MockWasmWebClient`), so nothing reaches a node, a prover or a faucet. `spec/mockchain-sandbox.md` has the spike's findings and the plan (PRs A to F). PRs A, B and C are in: the client, its default store, the chain kept across reloads, crash recovery, then transactions and accounts, then saved projects and one tab at a time. The home card is still commented out and the switcher entry shows in dev builds only (`import.meta.env.DEV`, for `e2e/mockchain-sandbox.spec.ts`); the Simulate tab doesn't work on `mmck` yet (PR D).

- The React SDK's `MidenProvider` takes no client: it calls `WasmWebClient.createClient(rpcUrl, …)`. `lib/miden-client.ts` replaces that static with `mockAwareCreateClient` (`lib/mock-chain.ts`), which returns a mock client for the sentinel `networks.mmck` (`"mock"`, which the SDK's `resolveRpcUrl` passes through) and calls the SDK's for every other URL. An SDK bump that changes how the provider creates its client breaks this silently: `mmck` would try to reach a node at "mock".
- `lib/mock-chain.ts` imports nothing from the SDK at run time (types only), so its unit tests run on plain node with fakes. Keep it that way: the SDK doesn't load there.
- `provers.mmck` is unset. With `"local"` the React SDK hands the mock client a local prover and it generates a real proof (over 30 s for a wallet); without one it uses its own, which doesn't prove.
- The chain lives in the client's memory, not in its store, and `exportStore()` leaves it out. It's saved to the IndexedDB database `PlaygroundMockChain` (no "miden" in the name, as for `PlaygroundProjects`) when it's created, replaced, and after a block (`proveMockBlock`: nothing else produces blocks, and no caller uses it yet). The factory gives it back to the client on load. A store ahead of its chain hangs initialization with no error, so whatever changes one must change the other.
- The store's name is fixed by the SDK: `mock_client_db`, the one the Simulate tab's client deletes and uses (`simulation.md`). Two mock chains never share a genesis, so two clients can't share the store.
- `defaultStore("mmck")` seeds no genesis header and no protocol config: each mock chain has its own. After a store import, `popState` replaces the live client's chain (`replaceMockChain`): with the one saved with the store (`State.nextMockChain`, a saved project's), or with a new one (null), which writes its genesis to the store. `replaceMockChain` calls `createMockClient` on the wasm client under the wrapper, an internal the SDK's worker calls the same way on each sync; it's needed because a new sandbox on the same network doesn't re-create the client.
- A saved project on `mmck` carries its chain (`Project.mockChain`, dumped after the store is exported: a store behind its chain syncs, a store ahead of it never does). `isRestorable` refuses a `mmck` snapshot without one. A chain the client can't read (another SDK version) fails the import like a refused store, and `popState` falls back to a new sandbox.
- One tab at a time: every tab shares `mock_client_db`, and each would run its own chain over it. The factory takes a Web Lock (`mockChainTabLock`) before it creates a mock client and frees it when the app's client is a real network's again; the browser frees it with the tab. It's one hold for the tab, shared by the clients created in a row (StrictMode, a restart). A tab that can't get it shows "the MockChain sandbox is open in another tab" with Retry (a reload), and no reset: the data is the other tab's. A tab on another network isn't held back, and its Simulate tab still deletes `mock_client_db` under the sandbox (PR D).
- A fresh `mmck` state has no USDCx Faucet entry: the chain has no public faucet.
- The mock RPC panics on an account its chain doesn't hold (`mock.rs:748` in miden-client 0.17.5), and the SDK never settles the call or any after it. The panic is in the client's worker for a call that runs there, and on the page's thread for the others (`importAccountById`: the page gets an uncaught `RuntimeError: unreachable`). The factory watches both for the client it returned, until the next client is created. On a crash it terminates the client and `MidenProvider` (`components/providers/miden-provider.tsx`) builds a new config, which makes the SDK's provider create a client on the saved chain, with a toast. A restart that crashes within `STARTUP_CRASH_MS` isn't restarted again (the store, the chain or the app state is what crashes it): the "Failed to initialize" screen shows, whose "Reset local data" also deletes the saved chain. So does an outdated `mock_client_db` deleted on load (`deleteOutdatedMidenStores`). Any uncaught WASM trap on the page counts while `mmck` is the network, whichever module raised it.
- Nothing produces blocks on the mock chain. Every submit proves one: `submitNewTransaction` (`hooks/use-transactions.ts`) and the account commit below call `proveMockBlock`, then `sync()`. `useTransaction` syncs too, but before the block exists. A new path that submits a transaction must do the same, or it stays pending.
- No funding: the mock chain charges no fee and has no faucet API. On `mmck`, `fundAccount` (`hooks/use-fund-account.ts`) submits an empty transaction, which puts the new account on chain (nonce 1), so whatever expects a committed account works.
- The app's sync loop (`network-badge.tsx`) runs on `mmck` as elsewhere: it's what lists notes. `clientGetAllInputNotes` skips its stateless `RpcClient` there (it can't reach a chain that lives in the client), so the notes keep their records' metadata. `clientGetLatestBlockNum` and `clientGetNotesById` still build one for `localhost`: don't call them on `mmck` (tutorial 3's mint button does, and tutorials don't run there).
- Nothing is sent for verification on `mmck`, neither a deployed account's packages nor a custom note's script (the registry has no MockChain, the API answers 400). The verify dialogs on the account and note pages still show and post: no PR has them yet.
- Import account is hidden on `mmck`: an id the chain doesn't hold is the crash above. A restarted client transacts: checked on 2026-11-19 by a page-thread panic from Import account (then visible), followed by a wallet created and committed in the same page. A crash in the worker wasn't reproduced.
- A new `mmck` sandbox starts with the counter example's packages (`sandboxStarter`, `counterExampleStarter`), as a Mainnet one does: it needs `apps/api`.
- To try it by hand, run the dev build and pick "New MockChain sandbox" in the switcher.
