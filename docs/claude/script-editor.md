# Script editor (`/scripts/:id`)

`spec/editor-console-improvements.md` is the roadmap for the editor and console (15 scored items). Its status line says what's done and what's next; mark items done there, with their PR, as they ship.

- A compile's diagnostics come from api-compile as a list (the MASM wire format in the verifier repo's `spec/remove-rust/README.md`: `severity`, `message`, `file`, `line`, `column`, `length`, `label`, `help`), passed through by the API as `diagnostics` and kept on the script (`Script.diagnostics`). The editor's markers and the console's counts read the list (`lib/utils/diagnostics.ts`): `file` starts with the package's directory (`counter-account/counter_account.masm`, `diagnosticSourcePath`), `line` and `column` are 1-based like Monaco's, and a diagnostic without a position, or in another package's file, shows in the console only. The assembler stops at the first failing phase, so a failed build usually has one error. Warnings get warning markers and leave the script compiled.
- The console shows `stderr` (the API's `error` for a failed build, `warnings` for a successful one), the assembler's own rendering in miette's ASCII theme, and links its `<package>/<file>:line:col` locations to the editor (`splitLocations`). `cleanCompilerOutput` (`lib/utils/compiler-output.ts`, display only; "Show full output" shows the raw text) drops the `x syntax error` / `help: see emitted diagnostics for details` rollup miden-assembly renders around related reports: api-compile gets a build's warnings from a second build with warnings as errors, so a successful build with warnings has it too. The fixtures in `lib/utils/fixtures/compile-errors/` are real answers of the local api-compile through the API's `PATCH /scripts/:id` (the counter template broken six ways): re-capture them when miden-assembly or api-compile change the diagnostics or their rendering, and run `pnpm test` in apps/web (`node:test`, plain node).
- The API doesn't store `error` or `warnings` (a successful build's stderr): a script fetched from it has neither, so guard with `script.error ?? ""`.
- The console log (`lib/console-log.ts`) is in memory, per script id: not in `State`, so not persisted or saved with projects. e2e specs wait for a compile with `COMPILED` from `e2e/editor.ts`, not the console's text.
- The console's header bar repeats the latest log line. Keep it one text node (`[time] text`) and not a button: the specs' anchored regexes (`/^Compiled …/`) and `getByRole("button", { name: "Compile" })` (a case-insensitive substring) would match it too, and fail on two elements. For the same reason, the empty log's placeholder shows in the bar only.
- The console has two tabs, Output (the log) and Simulate (`simulation.md`), in its header bar before the status line. The log's tools (full output, copy, clear) show on Output only, and the first two hide under 360 px.
- The Compile button sits in the tabs row, above the editor (`hooks/use-compile-script.ts`), not in the console. Tutorial steps say where it is (`deploy-a-counter-contract/step2.tsx`, `timelock-p2id-note/step3.tsx`): update them when it moves. Tutorials name the page's tabs, files and console too (`deploy-a-counter-contract/step2.tsx`, `timelock-p2id-note/step3.tsx` and `contract-verification/step2.tsx`, which say the console sits under the editor, `your-first-smart-contract-and-custom-note/step3.tsx`, `interact-with-the-counter-contract/step2.tsx` and `step3.tsx`, which also names the Manifest tab's sections and the exports table's "Read-only" badge): grep `components/tutorials` after renaming any of them.
- Shortcuts (Cmd/Ctrl+S and +Enter compile, +J toggles the console, +L clears it) are one capture-phase `keydown` listener on the window (`hooks/use-script-shortcuts.ts`). The compile keys need an editable script (`compileEnabled`), the console's a console (`consoleEnabled`); a disabled key is left to the browser. Not `addCommand`: standalone Monaco shares `addCommand` bindings across the page's editors. Per-editor commands use `addAction` (the "Toggle Minimap" action).
- Editor settings (the gear in the tabs row: minimap, font size) apply to every editor and script, in localStorage (`lib/editor-settings.ts`, key `editor-settings`). The split sizes are in localStorage too (`script-editor-layout`, saved after drags only), as is the console's "Show full output". None is in `State` or saved with projects.
- Every script is created and compiled through the API, in tutorials too (the stand-in some of them used, `lib/mock-api.ts`, is gone). Its scripts had `<example>_<uuid>` ids, and a tutorial run saved back then can still hold one: `compileScript` (`apps/web/lib/api.ts`) refuses an id that isn't a UUID with a message asking to restart the tutorial. Run tutorials 6, 7 and 8 after changing the script page.
- The page's tabs are Explorer and Manifest (the MASM tab went with Rust: a `?tab=masm` link opens the Explorer). The Explorer lists the script's files (`script.files`: its source `<name with _>.masm` and `miden-project.toml`, named by `sourceFilePath` in `apps/api/lib/source-file.ts`, which `lib/utils/script-files.ts` imports) and opens them as editor tabs, the source only at first. Only the source is edited, with the MASM language (`masm-highlighting.md`): the API generates the manifest, which shows read-only (Monaco language `ini`: there's no TOML). Built-in scripts have their MASM as their source and no manifest, the built-in libraries (`miden-core`, `miden-protocol`) no file at all: for those the Explorer tab is disabled with a tooltip and the page opens on Manifest. Read a script's source with `scriptSource` and its path with `scriptSourcePath` (`lib/utils/script-files.ts`), never a literal path. A state persisted before MASM that holds a Rust script is reset on load (`saved-projects.md`).
- Adding or removing a dependency patches `miden-project.toml` locally (`filesWithDependency`, in the API generator's format); the next compile replaces it with the API's. Keep the patch in step with `generateMidenProjectToml` in `apps/api/lib/toml.ts`.
- The Explorer tab stays mounted on the other tabs (`keepMounted`), and so does the source's editor while another file shows or its tab is closed: the hidden editor stays in the DOM and in `monaco.editor.getEditors()` (it's the first one). Scope e2e locators to the visible tab. The console shows on every tab of an editable script, and its links open the source in the Explorer. A read-only script has one only when it can be simulated (`canSimulate`, `lib/simulation/can-simulate.ts`: an account component, note or transaction script with a `masp`): no Compile button, the console opens on Simulate, and its empty log says "Simulation runs are logged here." (`readOnly` on `EditorConsole`). It shares the editable scripts' split sizes. The MASM built-ins, libraries and authentication components keep the bare tabs.
- `script.masm` is what a built-in script is assembled from in the browser (`assembledFromMasm`, `lib/utils/script.ts`: no package, a non-empty `masm`); its source file holds the same text. The API's scripts have an empty `masm` (the API stopped writing the column) and a package once compiled. Branch on `assembledFromMasm`, never on `masm` alone.
- On a phone (< 768 px) the source editor is read-only (Monaco's `readOnly` option, not the `readOnly` prop, so `onChange` stays attached). The tutorial steps that ask for code (7 step 2, 8 step 3, 12 step 2) have buttons that add it: the edits are in `lib/utils/tutorial-code.ts`, anchored on the starting sources (`apps/api/templates/counter-account.rs` for tutorials 7 and 12, `p2id-note.rs` for tutorial 8) and tested against them. Rerun `pnpm test` after changing those sources or the steps' code. The buttons edit the open editor's model (registered in `lib/source-editors.ts`), so Cmd/Ctrl+Z undoes them.
- The page wakes api-compile, whose container sleeps after 5 idle minutes: `useWakeCompiler` (`hooks/use-wake-compiler.ts`, in `pages/script.tsx`) calls the API's `POST /wake` (`apps/api/lib/wake.ts`) on open, and on focus or when the tab shows again, at most once per 4 minutes per tab and not within 4 minutes of a compile (`lib/compiler-wake.ts`). The route answers 204 at once and pings api-compile's `GET /` in `waitUntil`, at most once a minute per isolate, outside the compile rate limit; failures are ignored. Keep it off the home page and the app shell: each wake keeps the container up about 5 minutes.
- A script has an owner: the browser's owner token (`apps/web/lib/owner-token.ts`, localStorage key `owner-token`, one per browser), which every API call that creates or changes a script sends as `Authorization: Bearer`. The API stores its SHA-256 on the package and refuses a compile or a delete from anyone else with a 403 (`apps/api/lib/owner.ts`; a package without an owner, from before owners existed, is claimed by the first write that carries a token). A create or a write without a token is a 401, so tooling that calls the API sends one too (`apps/api/scripts`). A new API call that writes a script must send `ownerHeaders()`. `spec/share-and-fork-scripts.md` has the decisions.
- `/scripts/:id` opens anyone's script. `useScriptAccess` (`hooks/use-script.ts`) marks it `shared` when it isn't in the local state, or when the API says this browser can't write it (`writable: false`): the page then gets it with `readOnly: true`, so the read-only mode above applies, under a banner (`shared-script-banner.tsx`) whose Fork button copies the script and its dependencies (`POST /scripts/:id/fork`, no compile) into the workspace. No Fork during a tutorial. `use-script.ts` is in the app shell's graph (the header's breadcrumb), so it and `owner-token.ts` stay SDK-free.
- Share (the icon before the editor settings, and "Share script" in the scripts table's menu) copies the page's link, for the API's scripts only (UUID ids). The link serves what the API stored at the last compile: the toast says so for a draft. `e2e/share-and-fork.spec.ts` covers the owner, a visitor in a second browser context, and the banner at 320 px.
