# Read-only procedures

The account page's Invoke button (`components/account/procedures-table-row.tsx`) has two behaviours:

- A read-only procedure runs locally (`readWord`, `executeProgram`) and shows its result in the row, through the Invoke Procedure dialog when it takes arguments.
- A state-changing one always opens the dialog (`invoke-procedure-arguments-dialog.tsx`): its arguments if it takes any (button "Preview"), then a preview of the transaction (`TransactionPreviewForm`, shared with the Create Transaction dialog), which Submit submits. Without arguments it opens straight on the preview, executing once as it opens. The preview's execution (`previewProcedure` in `hooks/use-scripts.ts`) dispatches nothing: no `SUBMITTING_TRANSACTION`, so the page's Invoke buttons stay enabled. Submit (`submitNewTransaction`) executes again, so a sync in between can make the submitted transaction differ from the preview, as in the Create Transaction dialog. A failed execution shows its cleaned message (`cleanExecutionError`): a toast on the arguments, or in the dialog with Retry when there are none. Tutorials 6, 7, 10 and 12 name the "Preview" and "Submit" buttons.

A procedure's `readOnly` flag decides whether its Invoke button runs it locally (`canInvokeProcedure`). api-compile reads it from the MAST (`readOnly` next to the manifest in `POST /compile`, `miden-package-metadata/src/read_only.rs` in miden-source-code-verification): `true`, `false`, or `null` when it can't tell (a dynamic call, a direct syscall, a call into another user library).

- The API stores it in each export's `Procedure` (the `exports` jsonb column, no schema change). Packages compiled before api-compile reported it have none until their next compile, and neither do registry packages (api-registry doesn't store it).
- `isReadOnlyProcedure` (`lib/utils/script.ts`) resolves it to a boolean when a script is built: the flag when there is one, otherwise the `get…` name. A wrong guess only costs a local run whose changes are discarded. The Manifest tab's exports table shows the resolved flag as a "Read-only" badge (tutorial 6, step 3, names it).
- Built-in scripts set it by hand (`lib/types/default-scripts`), matching what the analyzer says for the same digests in miden-standards: re-check them after an SDK bump. `withDefaultScripts` replaces persisted copies, so a corrected flag reaches existing states.
- `callsForeign` travels with `readOnly`: the same MAST walk (`callsForeign` next to `readOnly` in `POST /compile`, `miden-package-metadata/src/foreign_calls.rs`), the same storage on each export, the same staleness (none on packages compiled before it, registry packages or built-ins). `true` when the export calls `tx::execute_foreign_procedure`, `null` when it can't tell (note and transaction scripts get `null`). Only `true` acts: the Simulate tab refuses the procedure when none of the script's dependencies resolves to an account it can stage (`docs/claude/simulation.md`) and the account page's Invoke dialog says the other account must be public and on chain.
- `parameters` travels with them too (`spec/procedure-parameter-names.md`): the parameters' names and types as the MASM source spells them, by export path (`parameters` next to `readOnly` in `POST /compile`, read from the source), the same storage on each export (`analyzedExports`, `apps/api/lib/package-exports.ts`), the same staleness (none on packages compiled before it, built-ins, transaction scripts). An export is listed only when api-compile found as many names as the signature has parameters. The registry returns it on the package, by path, and `packageToScript` copies it onto each export. The names are used, and a type's source name labels it (`NoteTag (u32)`): the layouts still come from the manifest (`procedureParams`, `procedureSignature`). The built-in basic wallet's hand-written signatures copy the basic-wallet template's manifest (`lib/types/default-scripts/basic-wallet.ts`): update them by hand from a compile of the template when api-compile changes its layout.
- The Invoke flow declares no foreign account: an `AccountId` argument is a plain argument. When a procedure reaches a public account through FPI, the client fetches it from the node at the reference block, for a transaction and for a local run (`executeProgram`) alike. A private foreign account, or one not committed yet, fails. Read in miden-client 0.17.5 (`src/store/data_store/mod.rs`: `get_foreign_account_inputs` fetches an unknown account on a cache miss) and verified on testnet on 2026-11-16, for a transaction (tutorial 10) and for a local run.
