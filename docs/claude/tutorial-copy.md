# Tutorial copy

Tutorial steps (`apps/web/components/tutorials`) have one wording for the desktop and the phone layout, not one per device.

- A tutorial's title, tagline, description, category, number, initial route, step count and whether it needs Bread Wallet (`requiresWallet`) live in `components/tutorials/meta.ts`, which its `index.ts` spreads (`...tutorialMeta("<id>")`): the home page and the project switcher show them from the app shell, before the SDK loads. A new tutorial gets its entry there, in order, and a loader in `components/tutorials/loaders.ts` (TypeScript fails without it). Its steps load on demand when it's opened (`loadTutorial`, and `useLoadedTutorial` for the panel); the rest of the app reads the meta. `loadTutorial` checks the step count against `meta.ts` in dev.
- Below `lg`, the pages' create buttons ("Create new account", "Create new script", "Add note"…) and the note page's "Consume note with …" show their icon only, as does the header's "Select Wallet" below `sm`: name them with `ButtonName` (`prose.tsx`), which shows the icon and the label. Labelled buttons and menu items take `<em>"…"</em>`.
- Refer to places outside the panel only if they hold on both layouts ("above the editor", "next to the procedure", "at the top of the page"), or link to them: on a phone the sidebar is hidden, and the panel sits at the bottom.
- "Click" is fine on both.
- A tutorial whose scripts are too big to embed in its `state` (a package built with debug info: the MASM counter is ~530 KB of base64) sets `starter` in its `index.ts`, as tutorials 6, 9 and 10 do (`counterExampleStarter` in `lib/utils/counter-example.ts`, which the Mainnet sandbox uses too; `readOnly` for a tutorial that only reads them; tutorial 6 keeps only `counter-account`). `enterTutorial` awaits it on a fresh start and appends its scripts to the state's; when the API is down the tutorial opens without them, with a warning toast. A resumed run keeps the scripts it was saved with, so one started without them never gets them: the steps that need them offer to restart the tutorial (`components/tutorials/missing-scripts-alert.tsx`, wrapped per tutorial), and those scripts are found by name, their ids being the API's UUIDs (`use-counter-script.ts`, `use-network-counter.ts`): a step's check on a script page compares the path with the found script's id.
- Set `requiresWallet` when a step has the user connect Bread Wallet and sign with it (tutorials 3, 4, 5, 8, 9 and 11): the first step then shows the "You need to install Bread Wallet" card while the extension is missing (`tutorial-step.tsx`). The other tutorials create their accounts in the Playground or deploy No Auth contracts, and must not show it.
- A tutorial that can't be completed for now (an upstream break) gets `unavailable` in `meta.ts`, a one-sentence reason: its card shows the reason with a disabled button, its project switcher item is disabled, `startTutorial` and `restartTutorial` refuse it and "Next tutorial" skips it. Saved progress is kept, and someone already in it stays in it. Mark its e2e spec `test.fixme` with the same reason, and remove both together.
