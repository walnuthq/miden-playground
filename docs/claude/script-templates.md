# Script templates

The "Create script" dialog creates scripts from `apps/api/templates/*.rs` (`lib/templates.ts`): each type with no example, and each example of the web app's `scriptExamples` (`apps/web/lib/types/script.ts`). Every one must compile. `pnpm templates:check` in `apps/api` creates and compiles each through the local API (`pnpm dev`, with api-compile running), then deletes them. Run it after editing a template, and after bumping the SDK, the api-compile image or `templates/project-template`: SDK API changes break templates silently (0.15 replaced `Asset.key: Word` with `Asset.id: AssetId`).

- The counter note and counter script examples import `counter_account` but come without it: tutorial 11 teaches adding the user's own `counter-account` script as a dependency. The check does the same (`userDependencies`), so keep it in sync when an example gains such a dependency.
- The check also compiles the code the tutorials add to a template (`tutorialEdits`, from `apps/web/lib/utils/tutorial-code.ts`): tutorial 7's increment and tutorial 12's `reset_count` on `counter-account`, tutorial 8's timelock on `p2id-note`. An edit whose anchor is gone from the template fails it too. Add a tutorial's edits there when it gains a snippet.
- Tutorial steps cite the templates' line numbers (`counter-account.rs` in tutorials 6 and 7, `p2id-note.rs` in tutorial 8; the step files say which in a comment): re-count them after editing a template. A step with several snippets cites a line only while no earlier snippet has moved it, and names the place otherwise ("at the beginning of the `script` method").
- A note script compiled from Rust calls its account's procedures by the MAST roots of the package it's compiled against, not the standard component's: the P2ID Note example is bound to `templates/basic-wallet.rs` (`lib/default-dependencies.ts`), whose `receive_asset` root isn't the standard basic wallet's. A standard wallet (the SDK's, Bread, Para) can't consume such a note ("procedure with root digest … could not be found"); an account deployed with the compiled `basic-wallet` can.
- The web app embeds that compiled package for tutorial 8, whose Test Wallet carries it (`apps/web/lib/tutorials/basic-wallet.json`, read by `basic-wallet.ts`): the template's source, the masp, its commitment and exports, as api-compile builds them under the name `basic-wallet` (digests depend on the package name). `pnpm templates:check` compiles it again and fails when the snapshot is out of date; `pnpm templates:sync` rewrites it (it runs the whole check with `--write`). Do it after editing `basic-wallet.rs` and after bumping the SDK or the api-compile image, with a local api-compile image that matches production's, as for the examples: a stale snapshot leaves the tutorial's note unconsumable, and no e2e sees it (the note is still locked when the spec ends).
