# Examples

The examples launched from the home page (`apps/web/lib/examples`) get their packages from `apps/api/examples`. Each example is a directory of MASM packages, one subdirectory per package holding its one `.masm` file (named after the package, as `sourceFilePath` names a script's), registered in `apps/api/examples/index.ts` with each package's name, kind, dependencies and hand-written schema. `POST /scripts/examples/:exampleId` creates the packages and compiles them through api-compile, in turn and each after the packages it depends on, as an import does. Later edits recompile through `PATCH /scripts/:id` as usual.

- No snapshot: a MASM build takes milliseconds, so the API compiles on launch. Measured on 2026-11-26 for the Counter Contract: 0.4 to 0.6 s per package on production's api-compile, 0.17 s for the whole launch against a local one. An SDK or api-compile bump needs nothing here: the next launch builds with it.
- An example's `ExampleMeta` can be `hidden` (`lib/examples/meta.tsx`): no card, no Projects entry, and a Mainnet or MockChain sandbox starts without the counter's packages while the Counter Contract is. No example is hidden today.
- A package's hand-written schema is in `examples/schemas.ts`, by example id then package name, kept while its source matches it (`lib/package-metadata.ts`, as for a template's). The Counter Contract's account uses the `counter-account` template's (`templates/counter-account.schema.ts`): the example deploys its account with the schema's slots (`useExamples`), so a lost schema deploys a counter without its storage map. A note's schema holds only while its source is byte for byte the shipped one: an example note's `metadata.template` names its package, `<example id>/<package name>` (`ExamplePackageRef`, `examples/ids.ts`), as a template note's names its template. `pnpm templates:check` launches every example and fails when a package doesn't compile, the account comes back without its storage schema, or a package loses a schema it was created with: run it after editing an example.
- Miden Bank (`examples/miden-bank`) has four packages: the `bank-account` component (`initialize`, `deposit`, `withdraw`, the read-only `get_depositor_balance`; slots `bank_account::initialized` and the `bank_account::balances` map, keyed by depositor and asset), `init-tx-script`, `deposit-note` (deposits its assets for its sender) and `withdraw-request-note` (typed storage: a faucet id and an amount). The bank pays a withdrawal in a public P2ID note to the request's sender, built with the standards' `p2id::prepare_note`, its tag from `note_tag::create_account_target` and its serial number from the request's. A balance withdrawn in full leaves no map entry. It started as a port of the upstream Rust tutorial's bank, with a smaller withdraw request: the Rust one also carried the serial number, tag, note type and the P2ID script root. `e2e/example-miden-bank.spec.ts` initializes it, deposits 1 USDCX from Bread and withdraws it back, on testnet.
- The Counter Contract's two packages started as copies of the `counter-account` and `counter-note` templates. Edit them in place; they may drift from the templates on purpose. Tutorials 6, 9 and 10 start from them (`counterExampleStarter`), and so do the Mainnet and MockChain sandboxes: their specs name the packages, procedures and slot (`counter_account::count_map`).
- The dev package with its debug info is what's stored and sent to the browser: the counter account is about 527 KB of base64 (395 KB of it debug info), the note 3 KB. Each launch stores it in a row and in the browser's persisted state.
- Register a new example in `apps/api/examples/index.ts` and its id in `examples/ids.ts` (plain node scripts such as `templates:check` can't import the bundled `.masm` sources), keyed by the web app's example id. The `.masm` files are bundled as strings by the Text rule in `apps/api/wrangler.jsonc`.
