# Saved projects and resumable tutorials

A saved project is the app state (`stateSerializer`) plus the client store as `exportStore()` dumps it, secret keys included (`apps/web/lib/utils/project.ts`, `hooks/use-projects.ts`). Two kinds (`ProjectKind`): leaving a tutorial saves it as a `tutorial` project and starting it again resumes it (`hooks/use-tutorials.ts`), its step shown from `State.tutorialProgress` without reading the snapshots; a sandbox or an example saved from the sidebar's Projects submenu is a `project` (`hooks/use-saved-projects.ts`, `components/lib/project-switcher.tsx`). Saving an example keeps its `exampleId` (the auto-deploy of its account), only the title changes.

- Snapshots go in their own IndexedDB database, `PlaygroundProjects`. Never put "miden" in its name, in any case: `clearMidenStorage()`, which runs before every store import, deletes every database whose name contains it.
- The database holds the `projects` store (the snapshots, megabytes each) and, since version 2, the `meta` store (`ProjectMeta`: kind, id, name, network, save time), written in the same transaction. The Projects submenu lists `meta` alone, most recently saved first, through a `["projects"]` query (TanStack Query) refreshed after each save and delete.
- The active project is `State.projectId` and `State.projectName` (persisted, so the app shell's title shows the name). Every state that starts a workspace has them empty, so New sandbox, Launch example and Start tutorial clear it. Save writes to the active project; Save as, and Save without one, ask for a name (`save-project-dialog.tsx`) and create one. That dialog and the delete confirmation (`delete-project-alert-dialog.tsx`) open through `State.saveProjectDialogOpen` / `deleteProjectDialogOpen` and render in `AppSidebar`, outside the switcher: on a phone the switcher is in the sidebar sheet, which unmounts it when it closes (and it closes so the dialog shows over the page). `AlertDialogAction` is a plain button, so the delete dialog closes itself before deleting. Leaving a project (opening another, a new sandbox, an example, a tutorial) doesn't save it. Delete removes the active project and leaves the workspace open, unsaved. No rename yet.
- Opening a project: `leaveTutorial()` (exports the current store), then `switchNetwork(project.networkId)`, then `pushState` with the record's id and name, the **live** `completedTutorials` and `tutorialProgress`, `nextStore` and a `fallbackState`: a fresh sandbox on the project's network (`freshSandboxState`). The order matters: `switchNetwork` re-initializes the client and unmounts the page (`MidenClientGate` shows the app shell until the new client is ready), `popState` then imports `nextStore` into the new network's store on remount. By the time an import fails, the previous store is cleared, so the fallback can't be the previous workspace.
- Snapshots carry the client version that wrote them. An SDK bump migrates them on import, but a rollback makes the SDK refuse them. `popState` then starts over from `fallbackState`: the tutorial from its start, a project as a new sandbox, each with its own warning toast.
- A network reset (testnet, or Partner Mainnet before public mainnet) invalidates them: `isRestorable` compares their genesis header with `genesisBlockHeader` in `lib/utils/store.ts`, so update that header with the reset. `loadProject` deletes a snapshot it can't restore; opening one reports it as an error.
